## 2. Rust core design (implements PRD §2.1–§2.3, §3.4, §7.3)

### 2.1 Shared state & lifecycle (implements PRD §3.4)

```rust
// packages/native/src/shim/state.rs
use std::sync::{Arc, Mutex, RwLock};
use sysinfo::System;

pub struct SharedState {
    pub system: RwLock<System>,
}

impl SharedState {
    fn new() -> Self {
        Self { system: RwLock::new(System::new()) }
    }
}

static STATE: Mutex<Option<Arc<SharedState>>> = Mutex::new(None);

/// Result of `init()`. `created_fresh` is the platform-agnostic signal that
/// `dart_sysinfo_flutter` reads to detect an un-disposed hot restart (PRD §3.4, §9.2).
/// The core has no knowledge of *why* state might already exist — only that it does.
pub struct InitResult {
    pub created_fresh: bool,
    pub abi_version: u32,
}

#[flutter_rust_bridge::frb(sync)]
pub fn init() -> InitResult {
    let mut guard = STATE.lock().expect("state mutex poisoned");
    let created_fresh = guard.is_none();
    if guard.is_none() {
        *guard = Some(Arc::new(SharedState::new()));
    }
    InitResult { created_fresh, abi_version: crate::abi::DART_SYSINFO_ABI }
}

#[flutter_rust_bridge::frb(sync)]
pub fn dispose() {
    let mut guard = STATE.lock().expect("state mutex poisoned");
    // Dropping the Arc<SharedState> here drops the RwLock<System>. Any in-flight
    // stream worker holding its own Arc clone keeps it alive until it observes
    // cancellation (see 2.3) and drops its clone — no use-after-free, no panic.
    *guard = None;
}

/// Internal accessor used by every domain module. Panics only if called before
/// `init()` — the Dart bridge guarantees `init()` runs first (see TDD §3.2).
pub(crate) fn state() -> Arc<SharedState> {
    STATE
        .lock()
        .expect("state mutex poisoned")
        .clone()
        .expect("dart_sysinfo native state accessed before init()")
}
```

**Design rationale:** a `Mutex<Option<Arc<SharedState>>>` (not `OnceLock`) is required specifically because `OnceLock`/`OnceCell` cannot be reset — and PRD §3.4 mandates that `dispose()` followed by a new call "re-inits cleanly." The outer `Mutex` only ever guards the *pointer swap* (cheap, uncontended in steady state); the inner `RwLock<System>` is what domain reads actually contend on, so a burst of concurrent snapshot calls across domains doesn't serialize behind unrelated init/dispose traffic.

### 2.2 Domain read pattern (implements PRD §2.1, §5.1)

Every domain module follows the same three-step shape — refresh under a write lock, read under the same guard, map to an FRB-exposed struct:

```rust
// packages/native/src/api/cpu.rs
use flutter_rust_bridge::frb;
use sysinfo::CpuRefreshKind;

#[frb(non_opaque)]
pub struct CpuCoreDto {
    pub name: String,
    pub vendor_id: String,
    pub brand: String,
    pub frequency_mhz: u64,
    pub usage_percent: f32,
}

#[frb(non_opaque)]
pub struct CpuInfoDto {
    pub architecture: String,          // System::cpu_arch()
    pub physical_core_count: Option<usize>,
    pub global_usage_percent: f32,
    pub cores: Vec<CpuCoreDto>,
}

#[frb(sync)]
pub fn cpu_snapshot() -> CpuInfoDto {
    let state = crate::shim::state::state();
    let mut sys = state.system.write().expect("system lock poisoned");
    sys.refresh_cpu_specifics(CpuRefreshKind::everything());
    CpuInfoDto {
        architecture: sysinfo::System::cpu_arch(),
        physical_core_count: sysinfo::System::physical_core_count(),
        global_usage_percent: sys.global_cpu_usage(),
        cores: sys.cpus().iter().map(|c| CpuCoreDto {
            name: c.name().to_string(),
            vendor_id: c.vendor_id().to_string(),
            brand: c.brand().to_string(),
            frequency_mhz: c.frequency(),
            usage_percent: c.cpu_usage(),
        }).collect(),
    }
}
```

`memory.rs` and `os.rs` mirror this shape exactly, against the field lists in TDD §4 below. **First-sample accuracy caveat (real, from `sysinfo` docs):** `cpu_usage()` is a diff-based metric and is inaccurate on the very first call after `init()`. This is not swallowed silently — see TDD §4.1's `ReadingUnavailable` mapping for "first sample."

### 2.3 Streaming (implements PRD §3.4, §5.4, §9)

```rust
// packages/native/src/api/cpu.rs (continued)
use flutter_rust_bridge::frb;
use std::time::Duration;

#[frb(sync)]
pub fn cpu_load_stream(sink: flutter_rust_bridge::StreamSink<CpuLoadSampleDto>, interval_ms: u64) {
    let state = crate::shim::state::state(); // this thread's own Arc clone
    std::thread::spawn(move || {
        loop {
            {
                let mut sys = match state.system.write() {
                    Ok(g) => g,
                    Err(_) => return, // lock poisoned -> stop silently, caller already torn down
                };
                sys.refresh_cpu_usage();
                let sample = CpuLoadSampleDto {
                    global_usage_percent: sys.global_cpu_usage(),
                    per_core_usage_percent: sys.cpus().iter().map(|c| c.cpu_usage()).collect(),
                };
                drop(sys);
                if sink.add(sample).is_err() {
                    return; // Dart side cancelled -> stop the loop, drop our Arc clone
                }
            }
            std::thread::sleep(Duration::from_millis(interval_ms));
        }
    });
}
```

**Cancellation contract:** `StreamSink::add` returns `Err` once the Dart-side listener is gone (FRB tears down the sink on stream cancellation). The worker thread checks this every tick and exits — this is what "the native worker stops when the last listener cancels" (PRD §5.4) actually resolves to at the Rust layer. The **interval clamp itself is enforced in Dart** (TDD §3.3), not here: Rust always honors whatever `interval_ms` it's given, so the clamp is testable in pure Dart without spinning up native threads.

### 2.4 Concurrency stress test (implements PRD §3.4, §8)

```rust
// packages/native/tests/concurrency.rs
#[test]
fn snapshot_and_stream_refresh_do_not_deadlock() {
    crate::shim::state::dispose(); // clean slate
    crate::shim::state::init();
    let handles: Vec<_> = (0..8).map(|_| std::thread::spawn(|| {
        for _ in 0..200 {
            let _ = crate::api::cpu::cpu_snapshot();
            let _ = crate::api::memory::memory_snapshot();
        }
    })).collect();
    for h in handles {
        // join_timeout via a channel + recv_timeout: fail the test (not hang CI) on deadlock
        assert!(join_with_timeout(h, std::time::Duration::from_secs(10)).is_ok());
    }
}
```

`cargo test -- --test-threads=1` (per PRD §8's `sysinfo`-reliability guidance) runs this file's test on its **own** thread but the test itself spawns 8 internal threads to contend the `RwLock` — this is the exact reconciliation the PRD footnote in §3.4 calls for.

## 3. Dart core design (implements PRD §5.1–§5.6)

### 3.1 `Reading<T>` and `SysInfoException` — implemented exactly as specified in PRD §5.2/§5.3, verbatim. No design decisions remain here; `lib/src/core/reading.dart` and `lib/src/core/sys_info_exception.dart` are direct transcriptions.

### 3.2 `SysInfo` base type and singleton (implements PRD §5.1, §5.6)

The PRD's example (`SysInfo.overrideInstance(FakeSysInfo(...))`) requires `FakeSysInfo` to be substitutable for the real `SysInfo`. Concretely, `SysInfo` is an **abstract base class** with instance members as its contract, plus the singleton/testing machinery as statics on that same class:

```dart
// lib/src/core/sys_info.dart
abstract class SysInfo {
  CpuDomain get cpu;
  MemoryDomain get memory;
  OsDomain get os;

  /// True if native state existed before this call created its binding.
  /// Consumed only by dart_sysinfo_flutter (PRD §9.2) — the core exposes the
  /// bit but never interprets it.
  bool get nativeStateWasPreExisting;

  Future<void> dispose();

  static SysInfo? _override;
  static _RealSysInfo? _real;

  static SysInfo get instance => _override ?? (_real ??= _RealSysInfo._create());

  static Future<void> disposeInstance() async {
    await _real?.dispose();
    _real = null;
  }

  @visibleForTesting
  static void overrideInstance(SysInfo fake) => _override = fake;

  @visibleForTesting
  static void resetForTesting() {
    _override = null;
    unawaited(disposeInstance());
  }
}

class _RealSysInfo extends SysInfo {
  _RealSysInfo._(this._initResult)
      : cpu = CpuDomainImpl(),
        memory = MemoryDomainImpl(),
        os = OsDomainImpl();

  factory _RealSysInfo._create() {
    final result = bridge.init(); // Rust init() — TDD §2.1
    AbiGuard.check(actual: result.abiVersion);
    return _RealSysInfo._(result);
  }

  final InitResult _initResult;

  @override
  final CpuDomainImpl cpu;
  @override
  final MemoryDomainImpl memory;
  @override
  final OsDomainImpl os;

  @override
  bool get nativeStateWasPreExisting => !_initResult.createdFresh;

  @override
  Future<void> dispose() async {
    await SharedStreamRegistry.instance.cancelAll();
    bridge.dispose(); // Rust dispose() — TDD §2.1
  }
}
```

`SysInfo.dispose()` in the PRD's illustrative surface (§5.7) is sugar for `SysInfo.disposeInstance()`; both names are kept — `dispose()` as the public one-liner consumers call, `disposeInstance` as the explicit static used by `resetForTesting`.

### 3.3 Streaming: clamp + broadcast + ref-count (implements PRD §5.4)

```dart
// lib/src/core/shared_stream_registry.dart
class SharedStreamRegistry {
  SharedStreamRegistry._();
  static final instance = SharedStreamRegistry._();

  final _entries = <String, _Entry<Object?>>{};
  final _loggedClamps = <String>{};

  Stream<T> get<T>({
    required String domainKey,          // e.g. "cpu.load"
    required Duration requested,
    required Duration minInterval,
    required Stream<T> Function(Duration clamped) createRawStream,
  }) {
    final clamped = requested < minInterval ? minInterval : requested;
    if (requested < minInterval && _loggedClamps.add(domainKey)) {
      // one-time debug-mode log per domain, per PRD §5.4 — never silent
      debugLog('$domainKey: requested $requested clamped to $minInterval');
    }
    final key = '$domainKey@${clamped.inMicroseconds}';
    final entry = _entries.putIfAbsent(key, () => _Entry<T>(createRawStream(clamped), () => _entries.remove(key)));
    return (entry as _Entry<T>).controller.stream;
  }

  Future<void> cancelAll() async {
    for (final e in _entries.values.toList()) {
      await e.controller.close();
    }
    _entries.clear();
  }
}

class _Entry<T> {
  _Entry(Stream<T> source, void Function() onFullyIdle) {
    controller = StreamController<T>.broadcast(onCancel: () {
      if (!controller.hasListener) {
        _sub.cancel();
        onFullyIdle();
      }
    });
    _sub = source.listen(controller.add, onError: controller.addError);
  }
  late final StreamController<T> controller;
  late final StreamSubscription<T> _sub;
}
```

Cancelling `_sub` drops the Dart-side FRB stream handle, which is what causes the Rust worker's `sink.add()` to start returning `Err` (TDD §2.3) — that's the end-to-end teardown path for "native worker stops when the last listener cancels" (PRD §5.4).

### 3.4 Snapshot TTL cache (implements PRD §5.5)

```dart
// lib/src/core/ttl_cache.dart
class TtlCache<T> {
  TtlCache(this.ttl);
  final Duration ttl;
  T? _value;
  DateTime? _fetchedAt;

  Future<T> read(Future<T> Function() fetch, {required bool forceRefresh}) async {
    final fresh = _value == null ||
        forceRefresh ||
        DateTime.now().difference(_fetchedAt!) >= ttl;
    if (!fresh) return _value as T;
    final result = await fetch();
    _value = result;
    _fetchedAt = DateTime.now();
    return result;
  }
}
```

## 4. Domain field mapping — P1 (implements PRD §5.1, §5.2, §6)

Every field list below is taken directly from the `sysinfo` 0.39 crate's public API (`System`/`Cpu` docs), not invented, so M1 implementation has zero ambiguity about what each Dart field maps to on the Rust side.

### 4.1 CPU (`CpuInfo`)

| Dart field | Type | Source (`sysinfo`) | `Reading<T>` mapping |
|---|---|---|---|
| `architecture` | `String` | `System::cpu_arch()` | plain (crate always returns a value) |
| `physicalCoreCount` | `Reading<int>` | `System::physical_core_count()` → `Option<usize>` | `None` → `ReadingUnavailable('not detectable on this platform')` |
| `globalUsagePercent` | `Reading<double>` | `System::global_cpu_usage()` | `ReadingUnavailable('first sample; call snapshot() again')` on the first read after `init()` — tracked via a per-`SharedState` "has refreshed once" flag |
| `cores` | `Reading<List<CpuCoreInfo>>` | `System::cpus()` | `ReadingUnsupported('CPU enumeration restricted on this platform')` on Android API levels where `sysinfo` documents restricted access |

`CpuCoreInfo` (`name`, `vendorId`, `brand`, `frequencyMhz`, `usagePercent`) fields are plain, non-`Reading` — if the core list itself is available, the crate always populates all four per-core fields structurally.

`CpuLoadSample` (stream element): `{ globalUsagePercent: double, perCoreUsagePercent: List<double> }` — plain, since a stream tick that can't produce a real sample simply doesn't emit (errors go through `onError`, per PRD §5.4, not through `Reading`).

### 4.2 Memory (`MemoryInfo`)

| Dart field | Type | Source | `Reading<T>` mapping |
|---|---|---|---|
| `totalMemoryBytes` | `int` | `System::total_memory()` | plain |
| `freeMemoryBytes` | `int` | `System::free_memory()` | plain (note: identical to `available` on Windows — documented, not hidden) |
| `availableMemoryBytes` | `int` | `System::available_memory()` | plain (identical to `free` on Windows/FreeBSD — documented) |
| `usedMemoryBytes` | `int` | `System::used_memory()` | plain |
| `totalSwapBytes` | `int` | `System::total_swap()` | plain |
| `freeSwapBytes` | `int` | `System::free_swap()` | plain |
| `usedSwapBytes` | `int` | `System::used_swap()` | plain |
| `cgroupLimits` | `Reading<CGroupLimits>` | `System::cgroup_limits()` → `Option<CGroupLimits>` | `ReadingUnsupported('cgroup limits are Linux-only')` on non-Linux; `ReadingUnavailable` if `None` on Linux |

The Windows/FreeBSD `free`≈`available` quirk is surfaced in dartdoc on both fields verbatim (from M3/M4's doc-coverage gate onward, per PRD §7.2) rather than papered over — it is real platform behavior, not a bug to hide.

### 4.3 OS (`OsInfo`)

| Dart field | Type | Source | `Reading<T>` mapping |
|---|---|---|---|
| `name` | `Reading<String>` | `System::name()` → `Option<String>` | `None` → `ReadingUnavailable` |
| `kernelVersion` | `Reading<String>` | `System::kernel_version()` | same pattern |
| `osVersion` | `Reading<String>` | `System::os_version()` | same pattern |
| `longOsVersion` | `Reading<String>` | `System::long_os_version()` | same pattern |
| `hostName` | `Reading<String>` | `System::host_name()` | same pattern (DNS-dependent; genuinely absent on some sandboxes) |
| `distributionId` | `String` | `System::distribution_id()` | plain (crate falls back to `std::env::consts::OS`, never empty) |
| `distributionIdLike` | `List<String>` | `System::distribution_id_like()` | plain (empty list is a valid value, not absence) |
| `kernelLongVersion` | `String` | `System::kernel_long_version()` | plain (crate substitutes `"unknown"` internally, never absent) |
| `uptimeSeconds` | `int` | `System::uptime()` | plain |
| `bootTimeSeconds` | `int` | `System::boot_time()` | plain |
| `loadAverage` | `Reading<LoadAverage>` | `System::load_average()` | `ReadingUnsupported('load average is not available on Windows')` on Windows — per crate docs, this is a known, permanent platform gap, not a transient failure |

`LoadAverage` = `{ one: double, five: double, fifteen: double }`.

```dart
  final FakeCpuDomain cpu;
  @override
  final FakeMemoryDomain memory;
  @override
  final FakeOsDomain os;

  @override
  bool get nativeStateWasPreExisting => false;

  @override
  Future<void> dispose() async {}
}

class FakeCpuDomain implements CpuDomain {
  FakeCpuDomain({CpuInfo? snapshot}) : _snapshot = snapshot ?? CpuInfo.allUnavailable();
  CpuInfo _snapshot;
  final _loadController = StreamController<CpuLoadSample>.broadcast();

  /// Test-only mutator — not part of [CpuDomain]. Lets a test change the
  /// canned value between assertions without re-constructing the fake.
  void setSnapshot(CpuInfo value) => _snapshot = value;

  /// Test-only injector for stream-based assertions.
  void emitLoad(CpuLoadSample sample) => _loadController.add(sample);

  @override
  Future<CpuInfo> snapshot({bool forceRefresh = false}) async => _snapshot;

  @override
  Stream<CpuLoadSample> load({Duration interval = const Duration(seconds: 1)}) =>
      _loadController.stream;
}
```

`MemoryDomainImpl`/`OsDomainImpl` real implementations and their `FakeMemoryDomain`/`FakeOsDomain` counterparts follow the identical shape against TDD §4.2/§4.3's field lists.

`CpuInfo.allUnavailable()` (and the memory/OS equivalents) is a named constructor every model provides — the safe, honest default for a fake nobody has configured yet, so a forgotten `setSnapshot()` call fails a test loudly (via a visible "unavailable" reading) rather than returning a plausible-looking fabricated value.

## 6. `doctor` tool (implements PRD §9.1)

`bin/doctor.dart`, run via `dart run dart_sysinfo:doctor`:

```dart
Future<int> main(List<String> args) async {
  final checks = <DoctorCheck>[
    RustToolchainCheck(),      // rustc --version vs rust-toolchain.toml; exact match required
    AndroidNdkCheck(),         // ANDROID_NDK_ROOT set + version >= r28
    XcodeCheck(),              // xcodebuild -version, macOS hosts only; skipped elsewhere
    CocoaPodsCheck(),          // pod --version, macOS hosts only
    BackendConsistencyCheck(), // Cargokit vs Native Assets wiring matches current SDK (PRD §3.3)
  ];
  var allOk = true;
  for (final check in checks) {
    final result = await check.run();
    print(result.format()); // "[OK] ..." / "[FAIL] ... -> fix: <exact command>"
    if (!result.ok) allOk = false;
  }
  return allOk ? 0 : 1; // nonzero exit is what CI and shell scripts key off
}
```

Each `DoctorCheck` returns a `DoctorResult { ok, summary, fixCommand }` — `fixCommand` is a literal shell command string (e.g. `"export ANDROID_NDK_ROOT=..."`, `"rustup target add aarch64-linux-android"`), not prose, so the "actionable output" requirement in PRD §9.1 is a structural property of the type, not a copywriting reminder.
